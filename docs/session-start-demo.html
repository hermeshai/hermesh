交互细节

发送状态跟着消息走，写在气泡下方；底部那一行只说 agent 在做什么。文案和样式全部沿用 Her 对话里已有的，不新增。

1 · 点发送
  • 立刻进会话页，输入框清空，气泡出现在底部，透明度 62%。标题先用消息的第一行。
  • Mac 在 400 毫秒内应答：气泡变实，中间不出现任何文字。
  • 超过 400 毫秒：气泡下方出现正在发送…，出现后至少停 500 毫秒。
2 · Mac 应答之后
  • 气泡变实，下方文字消失。不写「已送达」，底部出现工作中就是送达。
  • 底部只有四个词：工作中、思考中、处理中、回复中。启动 agent、等模型开口都算工作中。
  • 计时照旧从本轮开始算。
3 · 在哪里工作：单独一行
  • 气泡下面、agent 的第一步之前，单独一行，样子和工具步骤一样：分支图标、一句话、右侧箭头。只在第一轮出现。
  • 按新会话页的选择说：从 main 新建了分支 hermesh/s_…；先取回远程时是从 origin/main 新建了分支…；原地切分支是切到了分支 feature/login；原地不切是原地，在分支 main 上工作。
  • 超过 400 毫秒的步骤先显示进行中（文字扫光，和运行中的工具一样）：取回远程的 main、从 main 新建 worktree；更快的只显示结果。
  • 点开看细节：方式、分支、基于哪个分支、目录；原地切分支时写明原来在哪个分支。
  • 没建成：这一行变成 ⚠ 加原因，点开看完整原因，这一轮结束，底部那一行消失。直接再发一条就会重试。
  • 不是 git 仓库的项目（临时项目）没有这一行。
4 · 没发出去
  • Mac 离线：气泡保持变淡，下方等 work-mac 在线后送达和丢弃。底部不再另写「排队中」。
  • 被拒绝：气泡变实，下方没能送达：原因、再试一次、编辑。再试一次用同一个指令编号，不会建出两个会话；编辑把文字放回输入框。
  • 结果不明（超时、断线）：当作离线处理，继续用同一个编号重发。
5 · 会话里接着发
  • 会话空闲：和上面一样。
  • 一轮正在进行：消息进输入框上方的队列卡片，发送期间那一行变淡，被拒绝时在那一行给出再试一次。
顺带的提速
  • 立刻进会话页：点发送后没有反馈的时间从 0.75 秒降到 0。
  • 取回远程、建 worktree、切分支挪到本轮里做，发送请求先返回，正常网络下「正在发送…」就不会出现。这几步的结果写在上面那一行里。
  • 不碰 git 的检查留在发送请求里（项目在不在、权限、原地目录是不是正被别的会话占用），没通过就是气泡下方的「没能送达」。
  • 基线快照和启动 agent 并行：Codex 省 0.4 秒，Antigravity 省 0.5 秒。
