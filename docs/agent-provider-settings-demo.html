Agent 提供方管理与验证 · 重新设计 Demo

重新梳理 4c779cc8 与系统设置 v3 的交互冲突：合并令人困惑的双验证按钮、将维护与来源信息收进标准分组卡片、把未安装的「安装详情…」空壳页改为原位确认表单 + 行内实时进度，并统一 Mac 与 iPhone 双端体验。

快捷定位：

为什么之前的界面奇怪，以及新版改了什么

1. 消灭「验证命令行工具」+「用此机账号测试模型」双按钮

旧版问题 4c779cc8 把内部工程验收表的两列（CLI 协议握手 vs 真实会话发 ready）直接暴露成了两个按钮；其中「验证命令行工具」甚至走 MaintainProvider 写接口，点一次还要签名并写一条安装任务记录。且 .set-acts 的 margin-top:-8px 直接导致说明文字压在按钮上。

新版方案 安装与发现阶段本就自动完成协议握手，日常不再暴露「验证命令行工具」。已安装工具统一在「命令行工具 / 安装与更新」卡片内提供单一右对齐按钮 「测试」：跑一轮无工具短对话同时验证 CLI 与账号，失败时在结果文案中自动区分是「CLI 握手异常」还是「账号未授权」。

2. 消灭「安装详情…」与空壳详情页

旧版问题 未安装列表一边写着「安装后会自动出现在这里」，右边又放「安装详情…」，且不解释为什么只有 Copilot CLI / OpenCode 有按钮、Cursor 没有；点进去复用已安装详情页，只剩大图标和左下角重叠的「安装」按钮。

新版方案 支持托管安装的项排在「未安装」前部，副标题明确写明 可由 Hermesh 安装 · npm，右侧直接给 「安装…」；外部安装项写明自动发现并附 「安装说明 ↗」。点击「安装…」弹出确认 Sheet（直接装入默认全局命令行目录，无写权限时回退 ~/.local/bin，终端立即可用），确认后在列表行内原位展示阶段进度，完成后自动升入已安装分组。

3. 视觉层级归位 & 双端统一

旧版问题 维护按钮插在 Hero 与「默认模型」之间喧宾夺主；「开启自动更新」做成了普通动作按钮；列表页底部「提供方任务记录」与「重新检测」拆成两行且空记录也常驻；iPhone 更是拆出了重复的 Installation and Updates 平行列表。

新版方案 详情页优先展示高频的「默认模型」，其下是规整的「安装与更新 / 命令行工具」卡片；「空闲时自动更新」回归原生 Switch 开关；任务记录仅在产生过安装/更新操作时与「重新检测」同行显示；Mac 与 iPhone 共享完全一致的单页结构。
